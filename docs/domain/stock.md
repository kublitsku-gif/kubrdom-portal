# Склад остатков

- Раздел снимка `stock` — то, что физически осталось и ждёт следующей стройки: `[{id, pid, n, mode, cost, store, qty, srcObjId, srcObjName, at, by}]`. Одинаковые позиции складываются в одну строку, нулевая строка удаляется.
- Кандидат в остаток — **перекуп** (`needOverBought`: куплено больше, чем требует смета). Это единственная величина, которую портал знает точно: фактический расход на объекте никто не считает.
- Сопоставление остатка с потребностью — по `pid`, имя только запасной путь для позиций без ссылки. «ОСП 30 м²» и «ОСП 18 м²» — разные фасовки, молча считать их одним товаром нельзя.
- `stockCoverNeeds` берёт по каждой потребности ровно нехватку, а не «сколько есть»: иначе на объект уезжает лишнее и там снова копится остаток.
- Выдача создаёт партию с `fromStock:true`. Такая партия **в кассу не проводится** — деньги за этот материал ушли раньше, на прошлом объекте, и второй расход был бы двойным счётом. Она же исключена из счётчика «не проведено», иначе финансист видит долг, который нечем закрыть. Приёмку не подделываем: материал ещё надо довезти, мастер отмечает её как обычно.
