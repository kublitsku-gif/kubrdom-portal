# Правила сборки: чертёж собирает смету

- **Правило говорит одно: К ЧЕМУ применяется смета из справочника** (`src/recipe.js`, раздел снимка `buildRules`, вкладка «⚙️ Правила» в Спецификации 2). «Обшивка стен ОСП — на стены каждого помещения», «Монтаж розетки — на каждую точку». Материалов у правила своих НЕТ: они уже описаны в смете, у неё есть экран, связь с каталогом и история цен, а вторая копия того же разошлась бы с первой на первой правке.
- Считает позицию **та же машинка**, что и спецификацию (`positionFor`, экспортирован из `src/spec.js` ради этого). Своя формула в правилах означала бы, что правило обещает одну сумму, а объект собирается по другой.
- Поля: `what` (`surface` / `point` / `room` / `part` / `house`), `k` (поверхность или вид точки), `scope` (`room` — строка на каждое помещение, `house` — одна на дом), `room` (фильтр по части имени помещения), `qty` (множитель), `stage` (0 = взять из сметы), `off`. Недонастроенное правило **молчит и говорит об этом** (`ruleReady`) — тихий ноль строк не отличить от «правило не сработало».
- **`allPositions` — один список на экран и на объект**: выбранное руками в справочнике плюс то, что дали правила, у каждой строки `from` (`est` / `rule`). `specBuildStages` собирает объект им же — иначе продали одно, а строят другое. `totals2` считает договор оттуда же.
- **Правила даёт только опытный раздел** (`specCtx` в admin.js: `specIs2(sh) ? buildRules : []`). По боевым спецификациям заведены договора, объекты и транши — молча изменить их сумму новым правилом нельзя, сначала правила обкатываются здесь.
- Фильтр помещений — по ЧАСТИ имени, без регистра: типов помещений модель не знает, а «санузел» в имени пишут всегда. Точных ключей у неё нет, и придумывать их значило бы вести второй справочник имён.
- **Правило правится ТАПОМ по чипу «откуда число»** в строке сметы (`est-why` → `estWhyEditor`): чип и есть правило, по которому строка посчитана, и читать его здесь, а править во вкладке «Правила» — значит каждый раз искать нужное среди сорока чужих. Редактор раскрывается у ПЕРВОЙ строки этой сметы (правило по помещениям даёт их несколько, три одинаковых редактора подряд — это не выбор), а само правило заводится ЛЕНИВО, по первой правке (`estRuleSet`): открытый редактор данных не создаёт — человек мог просто посмотреть, откуда взялось число. Новое правило повторяет нынешний счёт («на весь дом»), поэтому первый тап цену не меняет.
- **Правило для сметы ЗАМЕНЯЕТ её обязательную строку** (`ruledEstIds` в `allPositions`): «Контейнер — один раз на дом» и «Контейнер — по площади пола» это одна позиция, посчитанная по-разному, и в списке она обязана быть одна. Позиции ВЫБОРА (отделка комнаты, общедомовая опция) правило не трогает: там решение принято руками. «Убрать правило» возвращает счёт «как в справочнике».
- Правка правила пишется сразу в раздел снимка (`ruleSet`), отдельной кнопки «сохранить» нет — её нет нигде в панели. Имя помещения и множитель пишутся по `change`, а не по `input`: перерисовка на каждой букве выбивает поле из-под пальца.

- Вкладка по умолчанию только у админа (в `rolePermissions` её нет) — открывается ролям в «Права ролей» без правки кода.
