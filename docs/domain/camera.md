# Съёмка фото/видео работ: своя камера в WebView

- Кнопки «📷 Снять фото» / «🎥 Снять видео» — `<label>` со скрытым `<input type=file capture>`. В обычном Chrome/Safari `capture` сразу открывает камеру.
- **Во встроенном браузере Android (WebView) `capture` игнорируется** — Telegram отдаёт выбор файла системе, и открывается галерея. Бригадиры входят через кнопку «Портал» в боте (Mini App), поэтому Валера снимал камерой телефона и выбирал снимок из галереи (2026-09-14).
- `src/camera.js` → `installInPageCamera(window)` (зовётся в `boot()`): только при `; wv)` / `Telegram-Android` в user-agent перехватывает тап по такому label, открывает свой видоискатель (`getUserMedia`), снятый файл кладёт в ТОТ ЖЕ инпут через `DataTransfer` и шлёт `change`. Обработчики загрузки (очередь фото, сжатие, Telegram-зеркало) не менялись.
- Видео пишем только в mp4 (`pickVideoMime`): webm Telegram не принимает. Нет mp4 у MediaRecorder или нет доступа к камере — экран с причиной и кнопкой «Открыть галерею» (тот же инпут, мимо перехвата). Хуже прежнего не становится.
- Запись видео сама встаёт через 3 мин (2 Мбит/с ≈ 45 МБ при лимите 50 МБ).
- Инпут берётся по id в момент съёмки: живой опрос мог перерисовать экран, пока человек целился.
- Новая кнопка съёмки = label с `input[capture]` внутри и id у инпута — больше ничего не нужно. Сторожит `test-camera`.
- Видео в Telegram-тему объекта уходит с `width`/`height`/`duration` и `supports_streaming` (`src/tgvideo.js`, клиент `videoMeta` → `&w=&h=&dur=`). Без размера кадра Telegram не разбирал телефонные ролики, и на Mac видео показывалось маленьким окошком (2026-09-17). Сторожит `test-tg-video`.
- **Видео привязано к РАБОТЕ, а не к объекту** (2026-09-20). Кнопка съёмки с `data-wid` (+`data-sid`) кладёт ролик в `w.videos`; без них — в `o.videos` (это «видео объекта целиком»). Решает `handleObjVideoFile(file, oid, tagName, at)`, где `at={sid,wid}`. Раньше всё валилось в `o.videos`, и к какой работе относится ролик, было видно только по подписи в Telegram.
- Тема в Telegram одна на объект в обоих случаях — меняется только, куда в снимке ложится ссылка. Имя работы по-прежнему идёт в название файла (`tagName`).
- Раздел «🎬 ВИДЕО ОБЪЕКТА» в карточке показывает СВОДНЫЙ список: свои ролики + все ролики работ (у чужих в строке стоит «🔨 <работа>», удаление уходит в `obj-del-work-video`). Не сводить его обратно к `o.videos`: админ смотрит карточку объекта, и раздел показывал бы «нет», пока по работам лежит десяток видео.
- Флаг «сейчас грузится» — `videoUploading` (бывший `objVideoUploading`): держит id РАБОТЫ для видео работы и id объекта для видео объекта. Карточка объекта считает себя занятой, если грузится она сама или любая её работа.
