# Заявки www.kubrdom.ru → CRM и Telegram

POST `/api/website-lead` — узкий серверный вход с отдельным секретом `WEBSITE_LEAD_TOKEN`. Такой же секрет задан у Pages `kubrdom-site`. Его нет в браузере; общий ADMIN_TOKEN не используется. Отсутствие секрета закрывает ручку (404). Запросы сайта проходят origin/размер/согласие/телефон/honeypot/rate-limit на стороне Pages.

`src/website-leads.js` добавляет клиента в `crmClients`, стадия `new`, источник «Сайт КубрДом». Один requestId соответствует одному содержимому: повтор не создаёт дубль, другое содержимое с тем же ID отклоняется. CRM и `website_lead_outbox` записываются одной транзакцией с проверкой версии раздела; при конфликте повторяем с новым снимком. Другие разделы не меняются.

Уведомления идут в существующую группу продаж `TG_SALES_CHAT_ID` через `TG_SALES_BOT_TOKEN`. Отдельный cron `*/5 * * * *` обрабатывает только эту очередь и не запускает напоминания/нейропродавца. При сбое доставка повторяется с задержкой; в редком случае неизвестного результата Telegram возможен повтор уведомления, но не клиента в CRM. Очередь хранит ID, сведения берутся из CRM. Удалённому клиенту уведомление не отправляется.

Сайт показывает успех только после подтверждённого сохранения в CRM; Telegram доставляется независимо. Названия целей сайта: `lead_received` и совместимая `lead_form` — подтверждённый приём, `lead_error` — ошибка, `sketch_received` — приём с эскизом. Эскиз остаётся в закрытом R2 сайта по ссылке 7 дней.

Тесты: `tools/test-website-leads.mjs` проверяет реальный SQLite: идемпотентность, откат CRM при сбое очереди, гонку с редактором, аутентификацию и повторы Telegram.
