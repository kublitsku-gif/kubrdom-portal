# Готовность работы в процентах

Код: `src/progress.js` (`workPct`, `isAutoPct`, `objPct`, `PCT_PRESETS`), сторожит `test-work-progress`.

- **Зачем.** Готовность была булевой (`w.done`). Бригадир за день сдвигал восемь работ по чуть-чуть — портал показывал ноль, счётчик «8 из 44» не менялся (Валера, 20.09.2026).
- **Гибрид, а не ручной ввод.** `workPct(w)` берёт, в порядке приоритета: отметку «Готово» (=100) → последний НАЗВАННЫЙ процент → оценку по часам (`факт/planHours`). Без плановых часов и без ручного процента — 0.
- **Оценка по часам не доходит до 100** (`AUTO_PCT_CAP=95`): «почти доделал» — не «сделано». Закрыть работу может только человек кнопкой «Готово». Такую оценку показываем приглушённо и с «~» (`isAutoPct`) — её никто не называл, и за отчёт бригадира её принимать нельзя.
- **Процент живёт в ЗАПИСИ ВРЕМЕНИ (`l.pct`), а не в работе.** Получается история: видно, как работа ползла по дням, и заметно «три дня пишет часы, процент стоит». Последним считается процент с самой поздней датой; при равных датах — внесённый позже (`lastPctLog`), чтобы запись задним числом не отматывала готовность назад.
- **`pct` в записи опционален.** Не выбрал — поля нет, и оценка по часам продолжает работать. Не заводить `pct:0` по умолчанию: ноль — это значение («не начинал»), а не «не указано».
- **Процент объекта взвешен по стоимости работ** (`objPct`), а не по их числу: «монтаж перегородок» за 50 000 не равен «повесить крючок» за 500. Смета без цен — считаем поровну. Одно и то же число в шапке объекта и в «Анализе стройки» — не разводить их обратно.
- **Процент НЕ двигает деньги.** Транши, «к оплате» и оплата труда остаются на `w.done` + приёмке этапа клиентом (решение заказчика, 20.09.2026). Строка «осталось N ₽» в шапке по-прежнему считается по закрытым работам. Как только процент начнёт влиять на выплаты, его начнут завышать, и он перестанет быть правдой.
- **Три места ввода, все пишут в ту же запись времени:** панель «УЧЁТ ВРЕМЕНИ» в строке работы (`obj-tl-pct` → `newTimeLog.pct` → сохраняется вместе с часами), шторка работы (`ws-pct`, выбирается ДО часов: тап по часам сразу пишет и закрывает шторку) и мастер «+ Запись» (`tl-wiz-pct` на шаге фото — часы там уже сохранены, правим запись по `tlWizard.savedLid`).
- Шаг пресетов — 10%: бригадир говорит «эту на 10, эту на 20», на четвертях такое не выразить.
