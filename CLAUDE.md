# Портал КубрДом

Портал строительной компании (бани и дома из контейнеров): CRM, объекты, сметы, договоры, снабжение, табель рабочих. Язык проекта и общения — русский.

Прод: **https://portal.kubrdom.ru** (свой домен обязателен: `*.pages.dev` / `*.workers.dev` в РФ режутся по SNI). Админ-панель: `/admin`.

## Навигация по коду (экономия токенов)

- **`admin.js` целиком не читать** — он не влезает в контекст. Сначала карта: `npm run -s codemap` (обзор: разделы с диапазонами строк, вкладки `t*`, маршруты Worker'а, экспорты `src/`) или `npm run -s codemap -- <слово>` (поиск по разделам, функциям, кнопкам `data-a`, маршрутам, экспортам → `файл:строка`). Потом Read с `offset`/`limit` по найденной строке.
- Кнопка из вёрстки ищется по имени действия: `npm run -s codemap -- notify-open` → строка обработчика в диспетчере `[data-a]`.
- grep по `admin.js` — только с номерами строк и обрезкой: `grep -n 'foo' public/admin.js | cut -c1-200` (в файле есть строки в тысячи символов).
- **Правила предметной области лежат в `docs/domain/`** — читать ТОЛЬКО файл своей темы по таблице ниже, не все подряд.
- Новое правило/гочу по теме записывать в её файл `docs/domain/*.md`; новая тема — новый файл и строка в таблицу. В этот CLAUDE.md — только то, что нужно в КАЖДОЙ задаче, иначе он снова раздуется (был 183 КБ).

## Архитектура

- **Cloudflare Pages** `kubrdom-portal` — фронт React/Vite (src/ → dist/) + **standalone админ-панель** `public/admin.html` + `public/admin.js` (~2,6 МБ vanilla JS, 30+ тыс. строк — основной код панели; целиком не читать, см. «Навигация по коду»).
- **Worker** `kubrdom-portal-api` (`src/worker.js`) + **D1** `banya-db` + **R2** `kubrdom-files` (фото/документы) + Telegram-зеркало фото/видео (бот, супергруппа с темами по объектам).
- `functions/api/[[path]].js` (Pages Function) проксирует `/api/*` → Worker на стороне edge — это обход блокировки workers.dev в РФ, НЕ ломать. Клиент ходит same-origin (`API_BASE=""`), файловые URL относительные (`/api/file/<key>`).
- Панель синхронизируется снимком всего стейта в D1 (`storage_key=admin_panel`), автосейв + live-опрос; авторизация заголовком `X-Admin-Token` (секрет `ADMIN_TOKEN` на Worker, fail-closed).
- **Сейв шлёт ТОЛЬКО изменившиеся разделы** (`dirtySections`). Не возвращать «шлём весь снимок»: сторож `base` на сервере проверяет ровно те `work_id`, что пишутся, поэтому запись всех разделов подряд означала 409 всем остальным на любую чужую правку. Форс-сохранение («Сохранить как есть») — исключение, оно шлёт всё и без `base`.
- Эталон стража (`updateServerCounts(items, onlyKeys)`) после такого сейва двигается только по отправленным разделам: по остальным сервер ничего не подтверждал, и записать туда локальный счёт значит обезоружить стража там, где вкладка устарела.
- **Опрос чужих правок спрашивает только версию** — `GET /api/state/:key/version` отдаёт `max(updated_at)`, и полный снимок (~1 МБ) тянется лишь когда версия выросла. Не возвращать опрос к «каждые 15 с тянем всё»: это мегабайт четыре раза в минуту на телефон бригадира. Если версия не пришла (старый Worker в окне деплоя отдаёт 404) — клиент сам падает на полный опрос.

## Деплой

- **Автодеплой: пуш в `main` → GitHub Actions** (Pages + Worker, секрет `CLOUDFLARE_API_TOKEN` комплексный). Ручной wrangler не нужен.
- **Пушить в `main` сразу после готовой правки — постоянное разрешение заказчика (09.09.2026), спрашивать не нужно.** Пуш = выкат на прод, поэтому перед ним обязателен зелёный `npm test` (CI гоняет их ещё раз и упавший тест останавливает выкат). Незаконченную работу держать в ветке.
- **Commit-сообщения — ASCII-чистые**: кириллица/грязные байты роняют Pages-деплой (`Invalid commit message [8000111]`).
- Новый секрет в deploy.yml: СНАЧАЛА `gh secret set <NAME>` (хоть плейсхолдером), ПОТОМ пушить код со ссылкой — иначе job падает.
- После `git push` не брать `gh run list --limit 1` сразу (поймаешь предыдущий прогон) — матчить run по `headSha`.
- Секрет `TG_BOT_TOKEN` задан вручную на Worker и переживает деплои — CI его не трогает.

## Сборка админ-панели (не ломать!)

- `npm run build` = `vite build` + `build:admin` (esbuild `public/admin.js` → `dist/admin.js`, target **es2017**).
- `admin.js` — ВНЕШНИЙ файл. НЕ инлайнить обратно в admin.html: >700 КБ инлайн-скрипта мобильный Safari не тянет (белый экран).
- target es2017: `?.`/spread транспилируются, но `async/await` остаётся НАТИВНЫМ. Не опускать target ниже — regenerator-полифил вешал iOS.
- Проверка после деплоя: в задеплоенном admin.js `?.` = **0 вхождений**. Размер — ориентир, а не константа: он растёт с кодом (на 2026-08-28 ~1650 КБ). Сверять надо порядок величины, а не точное число.
- Кириллицу esbuild экранирует в `\uXXXX` с ЗАГЛАВНЫМИ hex, поэтому `grep "Можно делать"` по задеплоенному бандлу **ничего не найдёт**. Проверять деплой по ASCII-маркерам (`data-a`-именам, id, классам).
- `<meta viewport>` содержит `maximum-scale=1` (лечит авто-зум iOS на инпутах) — не убирать.

## Критичные правила данных

- **Лимит D1: строка ≤ 2 МБ.** Снимок сохраняется одним транзакционным batch — одна раздутая строка откатывает ВСЁ сохранение. Поэтому файлы (фото, PDF, договоры) ВСЕГДА в R2 ссылками, НИКОГДА не base64 в стейт.
- Загрузка файлов: клиент жмёт фото до ≤1 МБ, Worker принимает img+pdf+office до 20 МБ по allowlist расширений (SVG/HTML запрещены — XSS).
- Частые микро-обновления UI — через `rerenderTab()` (частичная перерисовка `#tab-content`), не полный `render()` (дёргает скролл на iOS).
- **Три двери перерисовки: `fl()` — правка данных (render + автосейв), `rerenderTab()` — частичная перерисовка с автосейвом, `ui()` — ТОЛЬКО экран.** Экранный переключатель (свёрнутый блок, раскрытая справка, отмеченная в пачку строка, поиск, выбор этапа у строки) в снимок не идёт, и звать на него сохранение нельзя: каждый тап сериализовал весь снимок (~1 МБ), гонял по нему стражей, перерисовывал страницу целиком — и зажигал отметку сохранения, хотя сохранять было нечего.
- **Отметка сохранения — СОСТОЯНИЕ в шапке (`save-mark`, `saveMarkSet`/`saveMarkFace`), а не всплывашка в углу.** Четыре лица: «✓ сохранено» (ничего не ждём), «⟳ сохраняю», «✓ 12:46» (облако подтвердило; зелёное первые 10 с, дальше серое — зелёный обещает «прямо сейчас») и «• не сохранено» (страж, ошибка сети, неподтверждённые правки). Красит его `paintSaveMark` точечно, без `render()`. Дебаунс (`scheduleSave`) отметку НЕ трогает — он срабатывает и там, где слать нечего; про несохранённое честно знает только `apiSave`. Ошибку по-прежнему объясняет баннер `showSaveError`, статус её лишь называет. Сторожит `test-state-sync.mjs`.
- Паспортные данные шаблона договора живут ТОЛЬКО в localStorage (`kubr_ctTpl`), в снимок D1 не попадают — так и оставить.

## Тесты

- `npm test` гоняет все `tools/test-*.mjs` (~45 с), новый набор подхватывается сам; вывод тихий — строка на набор, полностью печатаются только упавшие (`-- --verbose` вернёт весь вывод). Зелёный `npm test` обязателен перед пушем; CI job `test` тоже блокирует выкат.
- **Пока правишь — гоняй только свою тему:** `npm test -- supply` (наборы с «supply» в имени), `npm test -- glue codemap`. Полный прогон — один раз перед пушем.
- Какой набор что сторожит и как устроен стенд панели в `node:vm` — `docs/domain/tests.md`.

## Гочи процесса

- **`gid()` обязан быть уникальным гарантированно** (`Date.now()` + счётчик вкладки + случайность). На id висят отметки закупки, фото и часы: два материала с одним id — это «куплено», поставленное не тому. Времени и трёх случайных символов не хватало — сборка объекта заводит сотню id в одну миллисекунду, а 36³ вариантов дают там коллизию примерно в каждом шестом прогоне; ловил это `test-spec-sheet` («id уникальны»), причём падал он редко и в CI, а не локально.

- В репо иногда работают параллельные Claude-сессии: перед коммитом проверять `git diff --stat`, коммитить только свои файлы (не `git commit -am`).
- Стейл-вкладка со старым кодом однажды затёрла облачный стейт (восстанавливали через D1 Time Travel). Против этого работают страж сохранения и «дожим при уходе» в admin.js — при правках зоны сохранения не ослаблять эти механизмы.
